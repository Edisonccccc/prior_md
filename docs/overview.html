§ 1

What the business actually does

In one line: translate a physician's chart into the format an insurer will pay against.

A patient goes home and needs six weeks of IV antibiotics. It costs tens of thousands of dollars. The insurer says: prove this money should be spent. That proof, plus the paperwork, is prior authorization — PA.

upstream

The physician

Writes the order — "Cefepime 2g IV q12h for 42 days" — informally, with the supporting facts scattered across a discharge summary and consult notes.

the middle · what we are automating

The PA specialist

Reads everything, picks the diagnosis code, computes the quantities, and produces the request in a rigid format. She is our SME.

downstream

The payer

Recognises codes and exact numbers only. Wrong format or wrong code means denial, and the patient does not get the drug.

§ 2

Medical terms, translated for engineers

Five words. Treat them as an external system's API contract.

ICD-10

An enum of diagnoses. One code per condition. The payer approves against the code, so choosing it is where almost all the judgment in this system lives.

J-code

The billing unit definition for an injectable. J0692 = cefepime, 1 unit per 500mg, so a 2g dose is 4 units. Pure multiplication.

day supply

Days covered, both ends inclusive. 07/24 → 09/03 is 42 days, not 41. A classic off-by-one, with money attached.

Part B / Part D

Two Medicare benefits with a hard boundary. Part D essentially pays only for FDA-approved uses; off-label gets an honest No. A drug given via an infusion pump is Part B, and Part D will deny it.

CMM questionnaire

The payer's form. Mostly Yes/No — but it is a branching tree, and measured across 21 real forms, 47% of questions are deliberately left blank.

that's all

Everything else (ORIF, I&D, MRSA…) is chart content. The AI reads it; you do not have to memorise it.

§ 3

The product goal

Input: a stack of chart PDFs. Output: one line that can be submitted as-is.

the deliverable · a "one-liner"

SOC 07/24/2026 – 09/03/2026 (42 days)
Cefepime 2g vial IV q12h · Total Qty: 84 vials · J0692 ×336
Daptomycin 500mg vial IV q24h · Total Qty: 42 vials · J0878 ×14,070
Dx: ______________

That, plus the CMM questionnaire answers and a set of warning flags, is her entire output for a case. Three of the four parts are arithmetic. The fourth — the diagnosis code — decides approval, and it is deliberately left blank until the judgment layer exists.

scope, confirmed by the SME 2026-08-03

A tool shared across multiple providers, doing medication adjudication: drug, quantity, J-codes, diagnosis code. Nursing codes and anything else that varies by institution are explicitly out of AI scope — the specialist adds those by hand.

§ 4

The core design insight

This job is two completely different kinds of work, and they must be handled differently.

deterministic → plain code

Dates, vial counts, unit conversion

42 days × 2 doses/day × 4 units/dose = J0692 ×336. Anything a calculator can do never goes to the LLM. It has to be 100% correct, reproducible and testable.

Status: done, and it reproduces her output character for character.

judgment → a constrained LLM call

Reading the chart, choosing the code, spotting contradictions

Example: the chart mentions orthopaedic hardware, and a "hardware infection" code exists — but the specialist deliberately avoids it, because under Part D that route runs into an FDA-approval problem. Same chart, two defensible codes, only one gets approved.

Status: not built. It now has what it was waiting for — see §6.

the second principle

Zero trust

The LLM's output is testimony, not fact. Every field must carry a quote from the source document; no quote and the pipeline halts. An honest "I don't know" passes with a warning. A fabricated value is stopped. That distinction is the pivot the whole design turns on.

§ 5

The architecture today

Five layers. The LLM appears at two of them; everything between is code.

① LLM
ExtractionChart → JSON. Fills fields only, each with a source quote. No arithmetic, no code selection.
② code
Zero-trust validationpipeline.py. Missing quote, missing start date, or a frequency outside the whitelist → hard stop.
③ code
Deterministic calculationpa_calc.py. Builds a real administration schedule, then folds it into day supply, dose count, vials and J-code units — four independent numbers.
④ LLM · gap
JudgmentICD route selection and CMM questionnaire answering. Neither exists. Both are designed; see the engine design doc.
⑤ human
Specialist reviewWorksheet → she approves or corrects → submits. Every correction flows back as a new exam question.
cutting across all of it

The eval set

Every case she got right becomes a permanent exam question, scored automatically on five dimensions (extraction / calc / coding / format / safety). Nothing ships unless all of them stay green.

the two unknowns that could make the design structurally wrong

How does a finished PA reach the payer? Pasted into a portal by hand, or submitted electronically? The first means the deliverable is a worksheet a person copies from. The second needs a submission state machine, receipts and retries — a different system.

What actually arrives at the start of a case? Not one real referral has been seen. The extraction contract and the PDF intake are both designed against guesswork.
